# ADR-002: Centralized Recommendation Engine

## Status

Accepted

## Date

2026-07-21

---

# Context

One of the primary goals of the AI Expense Tracker is to help users improve their financial health by providing personalized recommendations.

These recommendations are based on the user's financial data, including:

- Expenses
- Budgets
- Spending patterns
- Financial health metrics
- Analytics
- Future financial information such as income, assets, debts, and savings

As additional features are introduced—including AI coaching, notifications, dashboards, and mobile applications—multiple parts of the system will require access to financial recommendations.

Duplicating recommendation logic across different components would lead to:

- Inconsistent advice
- Duplicate business rules
- Difficult maintenance
- Increased testing complexity
- Higher risk of defects

The project therefore requires a single location responsible for evaluating financial rules and producing recommendations.

---

# Decision

The project adopts a centralized Recommendation Engine responsible for generating all financial recommendations.

Every recommendation must be produced by the Recommendation Engine.

No other component should independently determine financial recommendations.

The Recommendation Engine serves as the single source of truth for financial advice.

```
Financial Data
       │
       ▼
Recommendation Snapshot
       │
       ▼
Recommendation Engine
       │
       ▼
Recommendation Objects
       │
       ▼
API / Dashboard / AI Coach / Notifications
```

---

# Recommendation Pipeline

The recommendation pipeline follows these steps.

```
Expense Data
Budget Data
Analytics
Financial Health
Other Financial Information
        │
        ▼
Financial Snapshot
        │
        ▼
Recommendation Snapshot Adapter
        │
        ▼
Recommendation Engine
        │
        ▼
Recommendation List
```

The application layer prepares the data.

The Recommendation Engine evaluates business rules.

The API layer exposes the results.

---

# Recommendation Engine Responsibilities

The Recommendation Engine is responsible for:

- Evaluating recommendation rules
- Assigning priorities
- Categorizing recommendations
- Producing Recommendation objects
- Ranking recommendations
- Returning recommendations in priority order

The Recommendation Engine is **not** responsible for:

- HTTP requests
- Database access
- File storage
- User interface rendering
- AI-generated explanations

---

# Rule Organization

Each financial recommendation is implemented as an independent rule.

Examples include:

- Overspending
- Budget violations
- Low savings
- High discretionary spending
- Financial health improvements

Each rule should:

- Evaluate one business condition
- Produce zero or one recommendation
- Be independently testable
- Have no knowledge of other rules

Independent rules reduce coupling and simplify future enhancements.

---

# Recommendation Model

The Recommendation model represents a completed business recommendation.

It contains information including:

- Priority
- Category
- Title
- Message
- Action
- Rationale
- Source rule

The model also exposes computed information such as:

- Recommendation key
- Recommendation score
- Actionable status

These computed values are derived from the domain model rather than calculated by the API.

---

# Application Layer Responsibilities

The application layer prepares data for the Recommendation Engine.

Responsibilities include:

- Building financial snapshots
- Translating application models into recommendation snapshots
- Calling the Recommendation Engine
- Returning recommendation objects

The application layer does not evaluate recommendation rules.

---

# API Responsibilities

The API layer exposes recommendations to clients.

Responsibilities include:

- Request validation
- Response serialization
- Optional filtering
- Pagination (future)

The API must never implement recommendation business rules.

---

# AI Integration

Future AI coaching features will consume recommendations generated by the Recommendation Engine.

The AI should explain and expand upon recommendations rather than generate independent financial advice.

Example:

```
Recommendation Engine
        │
        ▼
Recommendation
        │
        ▼
AI Coach
        │
        ▼
Explanation
Action Plan
Educational Content
```

This ensures that AI-generated responses remain consistent with the application's financial rules.

---

# Benefits

This architecture provides several advantages.

## Single Source of Truth

Financial recommendations are generated in one location.

---

## Consistency

Every interface receives identical recommendation results.

Examples include:

- Dashboard
- REST API
- Mobile applications
- AI Coach
- Notifications

---

## Extensibility

Adding a new recommendation typically requires:

- One new rule
- One unit test

Existing rules remain unchanged.

---

## Testability

Each recommendation rule can be tested independently.

The Recommendation Engine can also be tested as an integrated unit.

---

## Maintainability

Business rules remain isolated from API and infrastructure code.

Changes to recommendation logic do not require modifications to the API.

---

# Consequences

## Positive

- Consistent financial advice
- Easier testing
- Simplified maintenance
- Reduced duplication
- Clear separation of responsibilities
- Future-ready AI integration

## Trade-offs

- Additional abstraction layer
- Larger number of small rule classes
- Snapshot adapters must evolve alongside new financial data

These trade-offs are acceptable given the long-term goals of the project.

---

# Alternatives Considered

## Recommendation Logic Inside Controllers

Rejected because business rules would become tightly coupled to the API layer.

---

## Recommendation Logic Inside Dashboard Services

Rejected because recommendations are required by multiple features beyond the dashboard.

---

## AI-Generated Recommendations

Rejected because AI responses may vary between requests and are difficult to validate consistently.

Instead, deterministic recommendation rules generate the financial advice, while AI is responsible for explanation and coaching.

# Future Considerations

Future enhancements may include:

- Recommendation history
- Recommendation dismissal
- Recommendation completion tracking
- Recommendation scheduling
- Notification preferences
- Personalized recommendation weighting
- AI-generated action plans

These features should extend the existing Recommendation Engine rather than replace it.

---

# Summary

The AI Expense Tracker uses a centralized Recommendation Engine as the single source of truth for all financial recommendations.

Business rules remain deterministic, independently testable, and reusable across every interface, while higher-level features such as dashboards, notifications, and AI coaching build upon the recommendations produced by the engine.
